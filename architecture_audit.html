Problem: 同步邏輯分散在多個 CLI 腳本與網關私有函式，呼叫端必須手動管理過期孤立 ID 清理與分批 upsert。

Solution: 將教學資產同步封裝為具備極小公開介面的深模組 TeachingSyncPipeline.sync()，將本地快取與雲端差分同步徹底內部化。

設計收益 (Wins)
  • locality: 同步與清理邏輯集中一處
  • interface shrinks: 刪除多個獨立同步腳本
  • leverage: 一個介面支援 CLI 與 API
  • adapter justifies seam: 本地與雲端端點解耦
ADR 決策建議：建立 TeachingSyncPipeline 作為雙 SSOT 同步唯一法定通道，禁止在業務路由或獨立腳本中直連 Supabase REST API。

CANDIDATE 03

隔離媒體資產儲存與 CDN 解析 (Isolate Media Asset Resolver)

Worth exploring ports & adapters
相關檔案 (Files)
07.Projects/StudentCRM/note_service.py 07.Projects/StudentCRM/hub_service.py 07.Projects/StudentCRM/scripts/optimize_teaching_images.py
Before: 圖檔直接捆綁進 Serverless Bundle
Git Repository ~74MB (147 images)
Vercel Serverless Function 逼近 50MB 硬上限
Markdown Inline Image Regex 每次請求逐筆重算
After: MediaAssetResolver 抽象層 Seam
Serverless Deployment < 8MB (Zero Media)
MediaAssetResolver (Adapter) 透明切換 CDN / Supabase / Local
NoteService Public Seam 一處完成 URL 解析與縮圖

Problem: 筆記圖檔直接打入 Vercel 代碼庫隨時有超過 50MB 部署失敗風險，且各處 service 充斥著自製的圖片正則解析。

Solution: 設立 MediaAssetResolver 介面，依環境透明提供本地 static 替換或外部雲端 Storage/CDN 網址。

設計收益 (Wins)
  • seam: 徹底解耦圖檔與部署包
  • locality: Markdown 圖檔正則集中單一模組
  • leverage: 一處定義圖片載入與快取
  • zero loss: 生產環境無破損風險
CANDIDATE 04

解耦測試環境與檔案系統 Seam (Introduce DocumentStore Seam)

Worth exploring local-substitutable
相關檔案 (Files)
07.Projects/StudentCRM/tests/test_teaching_sync_crm.py 07.Projects/StudentCRM/teaching_sync.py 07.Projects/StudentCRM/data_gateway.py
Before: 測試打擊實體磁碟 (39.63s)
// 測試 setup
shutil.copytree("01.Docs/teaching", tmp)
複製 700+ 個實體檔案至臨時磁碟目錄
IO 等待：約 32 秒 (佔比 81%)
After: 替換式 DocumentStore (< 2s)
// 測試 setup (Local-Substitutable)
store = InMemoryDocumentStore(sample_notes)
純記憶體字典比對，無需打擊真實磁碟
執行時間：< 1.5 秒 (加速 25 倍)

Problem: 同步測試因直接操作 700+ 個 Markdown 檔案的真實磁碟複製（copytree）導致 pytest 耗時近 40 秒，嚴重拖慢開發回饋迴圈。

Solution: 在教學資產讀取處引入 DocumentStore 抽象介面，測試使用輕量 InMemoryDocumentStore，生產環境使用 DiskDocumentStore。

設計收益 (Wins)
  • leverage: 測試回饋迴圈由 40s 縮至 <2s
  • adapter justifies seam: 記憶體與磁碟雙實作
  • zero loss: 生產環境無額外運行開銷
  • locality: 檔案 IO 分支不污染業務邏輯
