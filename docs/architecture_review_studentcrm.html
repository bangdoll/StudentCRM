問題：`main.py` 承載了超過 600 行的業務決策邏輯，HTTP 路由與業務計算高度耦合，任何規則調整都必須修改控制器。

解法：抽取獨立 `apple_ceo_service.py` 深模組，對外僅暴露 3 個極簡純函數，內部隱藏所有日期換算、四個月過期判定與勾稽細節。

收益 (Wins)：

  • 測試直接鎖定服務層，不需啟動 HTTP client。
  • 控制器大幅瘦身 600+ 行。
  • 效期邏輯獲得獨立單元保護。
  • 業務規則修改不波及路由。

2. 抽取學員領域服務 (Extract Student Domain Service)

Strong Recommendation in-process domain service
student_service.py
Files: main.py, student_service.py, data/students.json

問題：學員列表、別名比對、堂數統計與標籤篩選散落在多個端點函數中，重複搜尋與過濾開銷高。

解法：抽取 `student_service.py` 封裝學員索引快取、消歧義別名搜尋與關鍵字統計。

收益 (Wins)：

  • 學員別名查詢集中管理。
  • 消除跨端點重複比對邏輯。
  • 提供統一的統計指標運算。

Top Recommendation

立即實施深模組解耦 (Execute Deep Module Refactoring)

首要任務為將 `apple_ceo_service.py` 與 `student_service.py` 抽離，建立清晰的 Seam。重構後將 `main.py` 收斂為純粹的路由轉譯層，同時配合新增臨界值單元測試，達成 100% 回歸測試與零破壞發布。
