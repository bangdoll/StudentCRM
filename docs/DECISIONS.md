# 架構決策記錄 (Architecture Decision Record)

## ADR-003: 學員專屬 Learning Hub 與教練零密碼通行門禁架構

### 背景與問題
1. 蔡教練擁有數百堂一對一教學紀錄，需交付給學員高品質、免記帳密的專屬複習空間。
2. 避免公開網域直接暴露全體學員名冊與 CRM 後台數據（隱私防護）。
3. 確定學員結業後或暫停上課時之連結有效性規範。

### 決策內容

1. **教練端通行（Coach Passkey Gate: /coach/zzzz）**：
   - 採用與學員完全相同的「專屬密鑰連結」體驗，廢除傳統使用者名稱與密碼輸入表單。
   - 蔡教練透過私鑰網址 `/coach/zzzz` 一秒直通後台，系統設置 180 天 Session Cookie，支援 iPhone PWA 加入主畫面秒開。
   - 未經授權之訪客直接訪問根目錄 `/`、`/student/*` 或 `/api/*` 一律回傳 HTTP 403 並渲染 `templates/lock.html` 隱私保護頁。

2. **學員端學習空間（My Learning Hub: /my/{token}）**：
   - 採用無感 Token 專屬連結（Magic Pass），以學生之 UUID 進行 100% 視野隔離。
   - 學員僅能查看自身歷次課堂筆記、八堂修煉技能樹 (Skill Tree) 與課堂 3 張微行動卡。
   - 若學員竄改網址嘗試訪問首頁或他人頁面，立即觸發 403 門禁攔截。

3. **結業存取權限模型：方案 3（終生課堂資產庫模式）**：
   - 學員已完成之堂數與筆記永久開放存取，不設過期攔截。
   - 視為學員終生持有之付費數位學習資產，未續約時不再增加新堂數。
   - 極大化個人品牌口碑、轉介紹與學員好感度。

## ADR-004: 成效雷達與 CSM 續約決策系統架構

### 背景與問題
1. StudentCRM 過去聚焦於「課表、堂數與筆記查詢」，缺乏將教學歷程直接轉換為「續課決策、痛點跟進、流失預警與產品階梯對接」的商業決策層。
2. 需在完全遵循 `AGENTS.md` 零破壞與防蒸發原則下，實裝高流失預警、7天微行動卡追蹤、AI 導入四階段自動判定與 CSM 追蹤狀態管理。

### 決策內容

1. **雙層快取與寫入防護 (Hybrid Cache Pipeline)**：
   - 成效雷達資料儲存於 `data/effectiveness_radar.json`，由 `data_gateway.py` 統一納管讀寫。
   - 嚴禁直接覆蓋修改原始 `students.json`，隔離核心學員名冊風險。
   - 更新 CSM 跟進狀態（`POST /api/radar/followup`）時，自動觸發寫入前 `.bak` 備份與縮水熔斷保護。

2. **獨立深模組責任邊界 (Deep Module Isolation)**：
   - 核心計算封裝於 `radar_service.py`，契約宣告於 `schemas/radar.py`。
   - 路由端點收攏於 `routers/coach.py`（提供 `/radar` 戰情頁與 `/api/radar/*`），維持 `main.py` 與 `student_service.py` 的高內聚單純性。

3. **成效成熟度與微行動追蹤演算法**：
   - **AI 導入階段判定**：以學員課次為基準（Cycle 1-2=數位地基、Cycle 3-4=核心提示詞、Cycle 5-6=MVP自動化、Cycle 7-8=AI OS/陪跑），結合近 3 堂筆記關鍵字加權動態微調。
   - **7天微行動卡雙軌追蹤**：自動抓取最後一堂課的 3 張微行動卡，當距離上次上課 > 14 天且未開新課時，自動標記「⚠️ 任務卡停滯」，並提供一鍵複製 7 天追蹤五問客製化關心話術。

4. **產品階梯對接 (Product Ladder Mapping)**：
   - 依照 `Effectiveness_Radar_v1.md`，自動將成效狀態對應至產品階梯（數位基礎救援包、90分鐘工作流啟動課、MVP工作流建置、90天AI OS陪跑），提供教練續約與加購提案錨點。
